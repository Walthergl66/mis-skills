# PostgreSQL Types and Native SQL

Load this when choosing a PostgreSQL 16 column type, deciding between ORM query languages, or writing set-based SQL with `jsonb`, CTEs, window functions, or set operations.

## Type selection

| Situation | Type | Reject instead | Reason |
| --- | --- | --- | --- |
| Primary key, distributed writes | `uuid` with `gen_random_uuid()` | `bigserial` on a busy table | Sequence contention and id disclosure in URLs |
| Sequential, single-writer, join-heavy | `bigint GENERATED ALWAYS AS IDENTITY` | `uuid` | Smaller index, better locality, cheaper joins |
| Instant in time | `timestamptz` | `timestamp` | `timestamp` silently loses the offset |
| Calendar date only | `date` | `timestamptz` | A birthday is not an instant |
| Money | `numeric(19,4)` | `double precision` | Binary floating point cannot represent 0.1 exactly |
| Quantity that can be fractional | `numeric` | `integer` units | Avoid storing scaled integers and converting at the edge |
| Bounded count | `integer` with a `CHECK` | `integer` unchecked | Encode the invariant in the schema |
| Structured, read-heavy, no relational integrity | `jsonb` | child tables | Cheap to read, expensive to query and impossible to constrain |
| Structured, queried per key with `?` or `@>` | `jsonb` plus GIN | `text` | `text` forces sequential scans |
| Small ordered set of scalars | `text[]` | child table | Simple containment, no foreign key, awkward per-element index |
| Domain the database must reject | `CREATE TYPE ... AS ENUM` | `text` plus `CHECK` | Enum ordering is free; adding a value needs `ALTER TYPE` |
| Searchable natural language | `tsvector` | `ILIKE '%x%'` | GIN plus `ts_rank` is orders of magnitude faster |
| Hierarchical path | `ltree` | recursive CTE per query | One index serves ancestor and descendant lookups |
| Free text with typos | `text` plus `pg_trgm` | `ILIKE` | Trigram indexes make leading-wildcard search viable |

## Hard rules

1. Use `timestamptz` for every real instant. Reserve `timestamp` for data that is deliberately zone-less and documented as such.
2. Use `numeric` for money and set scale in the column definition. Java `double` and `float` are banned for amounts.
3. Do not use a sequence value as a business counter. Rollback consumes values, so gaps are expected and must be tolerated.
4. Do not model a relationship in `jsonb` when a foreign key is required. Integrity must be declarative.
5. Do not store a timestamp as a formatted string. Ordering, ranges, and timezone behavior all break.
6. Add a `CHECK` constraint for every rule the application would otherwise enforce only in a service.
7. Use `jsonb` for data whose shape is unstable and whose queries are whole-document reads, not for data you intend to join or aggregate by key.

## Sequences and identity

```sql
CREATE TABLE job (
    id          bigint GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    external_id uuid        NOT NULL DEFAULT gen_random_uuid() UNIQUE,
    status      text        NOT NULL,
    next_run_at timestamptz NOT NULL
);
```

- `GENERATED ALWAYS AS IDENTITY` protects against manual inserts of colliding values and is the default choice for a new table.
- `bigserial` is legacy sugar over a sequence and `GENERATED BY DEFAULT`; do not mix the styles in one schema.
- `uuid` needs the `pgcrypto` extension before PostgreSQL 13, and the `uuid-ossp` extension is never needed for `gen_random_uuid()` on PostgreSQL 16, where it is built in.
- UUIDv4 random ids scatter index pages. UUIDv7, ordered by time, keeps locality. If the application generates ids, choose v7 and use `insert ... on conflict` rather than read-then-write.
- Gaps are not a bug. A rolled-back transaction still consumes a value from a sequence because sequences are non-transactional.

## Extensions

| Extension | Enables | Cost |
| --- | --- | --- |
| `pg_stat_statements` | Statement-level timing and call counts | Must be preloaded in `shared_preload_libraries` |
| `pg_trgm` | Trigram indexes for `ILIKE` and similarity | Write overhead on indexed text |
| `btree_gin` | GIN index with btree equality on leading scalar columns | Smaller than a separate btree plus GIN |
| `citext` | Case-insensitive text with real uniqueness | Case-folding rules are locale dependent |
| `ltree` | Hierarchical path operators and indexes | Extension owned data, not SQL standard |
| `postgis` | Geospatial types and indexes | Large dependency, separate server tuning |

Prefer plain types plus a second lookup table over an extension when the requirement fits. A model stored as `ltree` inside one column cannot be joined, aggregated, or constrained like a real hierarchy.

## Native query patterns

### Set-based DML instead of per-row loops

```sql
UPDATE invoice
   SET status = 'OVERDUE',
       updated_at = now()
 WHERE status = 'OPEN'
   AND due_at < now();
```

One statement, one transaction, one set of row locks. The equivalent Java loop is N statements, N round trips, and a long transaction that blocks vacuum.

### Idempotent upsert

```sql
INSERT INTO webhook_delivery (endpoint_id, event_id, received_at)
VALUES (:endpointId, :eventId, now())
ON CONFLICT (endpoint_id, event_id) DO NOTHING;
```

Add `DO UPDATE SET ...` only when the caller actually needs last-write-wins semantics. `DO NOTHING` is the safe default for deduplication.

### Window functions

```sql
SELECT id,
       customer_id,
       total,
       row_number() OVER (PARTITION BY customer_id ORDER BY issued_at DESC) AS rn,
       sum(total) OVER (PARTITION BY customer_id
                        ORDER BY issued_at
                        ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW) AS running_total
  FROM invoice
 WHERE issued_at >= now() - interval '12 months';
```

An index on `(customer_id, issued_at DESC)` serves the window ordering and removes the sort node.

### Recursive CTE for a hierarchy

```sql
WITH RECURSIVE tree AS (
        SELECT id, parent_id, 0 AS depth, ARRAY[id] AS path
          FROM category
         WHERE parent_id IS NULL
        UNION ALL
        SELECT c.id, c.parent_id, t.depth + 1, t.path || c.id
          FROM category c
          JOIN tree t ON c.parent_id = t.id
         WHERE NOT c.id = ANY(t.path)
)
SELECT id, depth FROM tree ORDER BY path;
```

The `path` guard makes the recursion terminate even if the data contains a cycle that a foreign key alone does not forbid.

### `jsonb`

```sql
SELECT id, payload -> 'billing' ->> 'city' AS city
  FROM event
 WHERE payload ? 'billing'
   AND payload @> '{"billing": {"country": "ES"}}'::jsonb;
```

| Operator | Purpose | Index support |
| --- | --- | --- |
| `->`, `->>` | Field access returning `jsonb` or text | No direct index |
| `?`, `?&`, `?\|` | Key existence | GIN default ops |
| `@>` | Containment | GIN default ops, or `jsonb_path_ops` |
| `@@` | JSONPath match | Expression index on a function |
| `jsonb_path_query` | JSONPath extraction | Rarely worth indexing |

Index a derived value with an expression index when the query extracts a single field repeatedly.

```sql
CREATE INDEX event_billing_country_idx
    ON event ((payload #>> '{billing,country}'))
 WHERE payload ? 'billing';
```

Never build a key by concatenating untrusted input into a JSON path. Resolve the path through a fixed `CASE` map.

## Query language decision

| Situation | Layer | Note |
| --- | --- | --- |
| Predicate on a mapped column | JPQL | The mapping stays the single source of column truth |
| Predicate set assembled at runtime | Criteria API | Keep it inside a repository; do not leak a builder |
| Entity returned | JPQL | Managed entity, dirty checking, lazy rules apply |
| Projection or aggregate | Spring Data interface projection | No entity, no persistence context cost |
| Report, bulk DML, database-specific operator | Native SQL or `JdbcTemplate` | Assume only PostgreSQL forever after this choice |
| Dynamic sorting from user input | Native SQL with a `CASE` map | Never concatenate a column name |

## Parameter binding in native queries

```java
@Query(value = """
        SELECT id, status
          FROM invoice
         WHERE customer_id = :customerId
           AND (:status IS NULL OR status = :status)
         ORDER BY CASE WHEN :direction = 'DESC' THEN issued_at END DESC,
                  CASE WHEN :direction = 'ASC'  THEN issued_at END ASC
         LIMIT :pageSize OFFSET :offset
        """, nativeQuery = true)
List<InvoiceSummary> search(@Param("customerId") UUID customerId,
                            @Param("status") String status,
                            @Param("direction") String direction,
                            @Param("pageSize") int pageSize,
                            @Param("offset") long offset);
```

Use named parameters. Numbered placeholders such as `?1` are position sensitive in Hibernate 6 and make reordering unsafe. Never accept a raw sort direction; map it to a fixed set of branches.
